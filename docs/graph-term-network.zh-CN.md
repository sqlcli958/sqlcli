# 术语网络：语义层缺的是骨架，不是字段

> 状态：**未拍板**，只是把问题和判据钉下来。当前生效的术语模型见
> [术语即场景](graph-scenario-model.zh-CN.md)。

## 起因

「术语之间也可能有关系——『购物』可能由『会员』『订单』『购物车』几个术语组成。」

这句话戳破的不是一个缺失的字段，是**术语一直被当成检索标签，而不是业务的模型**。

## 术语实际承载六样东西，过滤只是最后一样

| | 回答什么 | 现在有吗 |
|---|---|---|
| 同义词 / 负向词 | 用户嘴里的词怎么落到数据上 | 有 |
| 定义（`description`） | 这个概念**是什么** | 有 |
| 落点（`--map`） | 这件事涉及哪些数据 | 有 |
| 入口与路径（`primaryTarget` + 子图） | 这些数据怎么连起来 | 有 |
| 口径（`filters`） | 查的时候要带什么 | 有 |
| **概念之间的结构** | **业务是怎么组织的** | **没有** |

最后一行不是前五行的附属，它是**语义层自己的骨架**。

## 缺了它，四件事做不了

1. **梳理业务** —— 产品目的里明写的一条。表结构给不了：表是实现，术语才是业务。
   agent 被问「这个系统在做什么」，只能报一堆表名。
2. **任务分解** —— 「购物流程有问题」要拆成哪几段查，现在只能靠猜。
3. **歧义消解** —— 「订单」在采购域和销售域不是一回事。区分靠的是它挂在哪个上级概念下，
   同义词列表消不了这种歧义。
4. **覆盖度评估** —— [图谱评估](graph-eval.md) 的 E4 要回答「哪些业务域没被覆盖」。
   没有域的结构就只能按表算覆盖率，而**表覆盖率是虚荣指标**（E4 自己的论证）。

## 「购物」和「购物车」不在同一层

按 [术语即场景](graph-scenario-model.zh-CN.md) 定的判据——**场景粒度 = 一个前端页面能完成的事**：

- `购物车`、`下单`、`会员中心` 各是一个**场景**，各有自己的入口表和 `filters`
- `购物` **不是场景**，它横跨多个页面，是一个**业务域**

所以要的不是「术语之间的任意关系」，首先是**术语之上多一层**。这个区别决定了数据结构：
平级的「相关」是一张任意图（要处理环、要定义「相关」是什么意思），
「由…组成」是一棵树，清楚得多。

## 现有模型能表达一半

`购物` 可以就是一条术语，`--map` 挂到三个子域的**入口表**，它的场景子图当俯瞰图看是够用的。
**这条不用写任何代码。**

真正表达不了的是：**各部分自己的口径**。`购物车` 的 `filters` 是 `status = 'active'`，
`订单` 的是 `state IN (0,1,6)`——**它们作用在不同的表上，不能 AND 到一起**。
一条扁平的 `购物` 只有一个 `filters` 列表，要么丢掉子域的口径，要么合出一个语义错误的条件。

次一等的问题是重复：`购物` 手动列全部 30 张表，以后 `订单` 加一张，得记得回来补 `购物`。

## 两个先前的结论作废

这两条都是「术语=检索标签」这个狭隘视角推出来的，记下来免得后面照着它们做：

| 先前结论 | 为什么作废 |
|---|---|
| 「组合关系的价值只在于能不能带上子域的 filters」 | 把语义层的骨架降级成了一个字段的附属。真正的价值在上面那四件事 |
| 「不要在图上画术语节点，和场景筛选信息重合」 | 如果术语之间有关系，**术语网络本身就是一张图**——业务视图，和表视图并列，不是在表视图上加东西。开发清单 S 组「明确不做」里那条「术语单开一页」随之待议 |

## 建模倾向（未定）

倾向**做成关系**而不是术语上的一个 `parts` 字段：既然它是语义层的骨架，就该和表之间的关系
同一个机制——有类型、有置信度、能遍历、能可视化。

代价要认：关系类型现在只有三个，技能里写死了「只有这三个」，加类型要动
CLI、校验器、图例、技能四处。

## 动手之前必须先钉死的三件事

这个仓库反复栽在**「写入口做完、消费侧没人做」**（血缘、`grain`、`com.sqlcli.profile`、
F4a/F4b、`value-domain` 五次）。所以读的那一端要先定：

- [ ] `search` 命中术语时，怎么把上级 / 同族带出来？带出来占不占结果位？
- [ ] 业务视图长什么样？是图谱页的第二种视图，还是别的位置？
- [ ] `schema eval` 怎么用它算**域**覆盖率，而不是表覆盖率？

三个定不下来，就还是一个写得进去、没人读的机制。
